# SVG 导入 / 导出的结构保真

用户可见契约在 [`docs/specs/svg-roundtrip/spec.md`](../specs/svg-roundtrip/spec.md)，
可执行影子在 [`test/e2e/svg-roundtrip.spec.js`](../../test/e2e/svg-roundtrip.spec.js)。
改导入、导出、源模板、持久化或图层顺序之前先看这份。

## 为什么不直接复用导入时的原始文本

最省事的做法是“没改就原样返回”，但用户改了一个图形后就不能整份返回，否则改动会丢；
反过来，每次都从编辑器模型重新生成，又会发生这些事：

- Paper.js 把 `rect` 展平成 `path`，把 `A` 圆弧转成 `C` 三次曲线，`Q` 也会丢；
- 源文件里的 `id`、注释、`defs`、`style`、属性顺序和数值文本（例如 `x="010"`）被重写；
- 每次导出、再导入都可能多出背景图形或让坐标漂移。

所以现在保留两份东西：**给用户编辑的模型** 和 **用于导出的规范化源模板**。
导出以源模板为底稿，只重写用户改过的元素。

## 导入流程

1. `readSvgDocument` 解析源文件。
2. `prepareSvg` 克隆出第二份文档：一份给 Paper 导入，一份留作导出模板。
3. `normalizeRoot` 规范根节点的尺寸与 `viewBox`：
   - 有 `viewBox` 时把根尺寸改成可表达的宽高，必要时加一个带 `transform` 的 `<g>`；
   - 根节点 `opacity` 移到这个包装组上，避免新增图形也被根透明度压暗。
4. `keyElements` 给每个可绘制元素一个稳定 key：
   - 工作副本把 key 写进 `id`，Paper 会把它带到 `item.name`；
   - 导出副本把 key 写进 `data-albedo-key`，原始 `id` 不动。
5. Paper 负责解析变换、继承样式和命中测试；图元几何尽量从源属性重建：
   - `rect`/`circle`/`ellipse`/`line`/`polygon` 在变换可表达时保持原生类型；
   - 路径优先直接解析源 `d`，这样 `A`、`Q` 和命令结构不会先被 Paper 化成三次曲线；
   - `polyline` 转成 `M`/`L` 命令。
6. `rememberSource` 记录每个模型图形对应的 key、导入时的规范签名（baseline）和祖先透明度。
   之后导出只比较签名，不改的就不碰。

根节点直接子元素 `<title>` 会作为导入标题带回：只有当前画布名称仍是“未命名画布”时才采用它，
已有自定义名称不会被导入覆盖。导出时根 `<title>` 始终写当前画布名称。

## 画布尺寸

画布尺寸跟文档状态走，不是 `viewBox` 解析失败：

- 空文档（包括新建的 960×640 空白画布）或替换示例文档：画布直接取源尺寸，
  所以 `viewBox="0 0 128 128"` 导入后是 128×128；
- 画布上已有图形：只增不减。否则一张 128×128 的小图会把 960×640 的构图裁掉，
  或让已有图形落在画布外；需要小画布时先新建空文档，或导入后手动改尺寸。

`viewBox` 只决定 SVG 内部坐标怎么映射；画布是编辑器 artboard，最终导出成根
`width`/`height`，两者不是一回事。

## 导出流程

`buildSourceSvg`：

1. 克隆源模板，更新根 `width`/`height`/`viewBox`，更新或补 `<title>`。
2. `reorderSource` 按当前图层面板顺序重排**同一父级**里的源元素；非图形兄弟节点保留原槽位。
3. 逐个模型图形：
   - 没有 key 的是新增图形，生成后追加；
   - 签名与 baseline 相同的是未改动图形，源元素一个字节都不碰；
   - 签名变了才重新生成，并尽量保持原生类型、路径命令和原 `id`。
4. 如果图形在带变换的组里，生成的元素会带一个逆矩阵，保证仍落在编辑器里的坐标。
5. 源模板里有、但模型里已不存在的 key，删除对应源元素。
6. 清掉所有 `data-albedo-key`，输出 XML 声明 + 序列化结果。

重新生成时的绘制属性：

- `keepSourcePaint` 在填充/描边/透明度都没变时，沿用源元素的 `fill`、`stroke`、虚线、
  线帽、线 join、marker、`vector-effect` 等属性；
- 渐变/图案引用会保留；这种画刷自带透明度，所以改用源元素自己的 `opacity`，
  避免把颜色里的 alpha 再乘一次；
- 变了填充或描边的图形按模型生成纯色，并保留原 `id`、`filter`、`clip-path`、`mask`。

## 持久化与撤销

- 模型文档：`albedo-svg-studio:v1`
- 源模板：`albedo-svg-studio:source:v1`（序列化后的源 SVG + 每个图形的 key/baseline/祖先透明度）

`saveNow` 先保存文档，再保存源模板。`sourcePersisted` 用来避免每次编辑都重新序列化整份源文件；
导入、撤销/重做、新建文档都会把它置回 false。源模板写不进去时会删掉旧键，
避免下次打开拿一份和当前文档对不上的模板。

撤销/重做不把源模板放进文档快照，而是用 `sourceByDoc` 记住导入边界的文档快照对应哪份模板：
撤销一次导入能回到上一份模板，重做则回到新模板。

## 追加导入（合并）

第二次导入不是替换，而是把新内容并进已有模板：

- 先克隆已有模板，保证撤销栈里引用到的旧模板不会被改；
- 新文件的 id 与已有 id 冲突时，给新文件的所有 id 加前缀，并同步更新 `href`/`url(#…)`；
  根节点自己的 `url(#…)` 也一起改；
- 新文件的 key 统一加前缀，避免和旧 key 撞；
- 新文件根节点会被换成一个 `<g>`，把根级的 `fill`/`stroke`/`style`/`opacity` 等继承属性带过去；
- `title` 不合并，导出时用当前文档名统一生成。

## 已知边界

- **不是字节级一致**：根节点的 `width`/`height`/`viewBox` 会规范化，会补/改 `<title>`，
  必要时会加一个坐标包装 `<g>`。契约保的是元素类型、数量、坐标、命令类型和未改动标记。
- **带不可表达变换的图元**：例如 3D 或 CSS transform 下的 `rect`，未改动时仍按源标记保留；
  一旦编辑，模型只能按 `path` 生成。这是显式降级，不是静默丢结构。
- **CSS class/style 的间接样式**：未改动时原样保留；改动后的元素只沿用源元素的绘制属性，
  不复制 `class`/`style`，避免把 CSS transform 一起带进来。
- **新增图形与跨组层序**：新增图形追加到根；层序重排只处理同一父级里的源元素，
  不把元素搬进/搬出源组。图层面板跨组拖拽后的视觉顺序仍可能与导出不同。
- **不可编辑内容**：`text`、`image` 不进入模型，未改动时随源模板原样保留；
  整个文件没有可编辑图形时导入会拒绝并提示，不会生成一份空文档。
- **合并时的 CSS `#id` 选择器**：id 冲突会改 id 并同步 `href`/`url(#…)`，
  但不会重写 `<style>` 文本里的 `#id` 选择器；依赖 id 选择器的复杂样式在合并后可能失效。
- **存储配额**：源模板很大时 `localStorage` 可能写失败；此时会丢模板并回退到重新生成，
  但不会拿旧模板冒充当前文档。
